# Telemetry Generator

The telemetry generation tool is an early version (v0.1) software designed to help generate and test telemetry data. It utilizes the Invoke-AtomicRedTeam framework to map sub-categories to their corresponding atomic red team tests in order to generate the telemetry. This mapping information is stored in the config.json file, which the tool reads and executes the techniques accordingly.

Users have the flexibility to execute either one technique or all of the techniques by passing the -Name parameter (default=All). This makes it easy to generate telemetry and test it against the comparison table of the project, ensuring alignment and accuracy.

However, it is important to note that some sub-categories cannot be tested using this tool, such as USB Mount/Unmount and everything from the EDR-SysOps category. Despite these limitations, the telemetry generation tool serves as a valuable resource for generating and testing telemetry data in accordance with the Invoke-AtomicRedTeam framework.

## Self-contained toolkit scripts

Four sub-categories are generated by self-contained PowerShell scripts in this directory instead of Atomic Red Team tests. They need no internet access and no downloaded payloads, which makes them suitable for locked-down or offline endpoints.

| Script | Sub-category | Technique |
| --- | --- | --- |
| `NamedPipe\Invoke-NamedPipe.ps1` | Pipe Creation / Pipe Connection | T1559 |
| `WmiPersistence\Invoke-WmiPersistence.ps1` | WmiEventConsumerToFilter / WmiEventConsumer / WmiEventFilter | T1546.003 |
| `BitsJobs\Invoke-BITSJob.ps1` | BITS Jobs Activity | T1197 |
| `DriverLoadUnload\Invoke-DriverLoadUnload.ps1` | Driver Loaded / Driver Unloaded | T1685 |

They appear in `config.json` under a step named `Custom` with a `Script` path relative to this directory and optional `Arguments`. Each script cleans up after itself and reports its outcome through the exit code captured in the run log.

Notes:

- The BITS script must run in an interactive logon session. BITS file operations from a network logon (for example a bare WinRM session) fail with `0x800704DD ERROR_NOT_LOGGED_ON`. When driving the generator remotely, run that category through a scheduled task in the logged-on user's session.
- The driver script loads a stock in-box driver through the service control manager. Most in-box drivers do not implement an unload routine, so the stop request fails with error `1052` and the driver stays resident until reboot; `rdpdr.sys` does unload and is the first default candidate, so a default run produces both Driver Loaded and Driver Unloaded telemetry. Pass `-DriverPath` with another unload-capable driver when needed, and reboot the endpoint after extended runs to clear resident test drivers.
- Each sub-category writes a per-run result row to `<Sub-Category>.csv` in the generator directory (invalid file-name characters in a sub-category name are replaced with `-`, so `Key/Value Creation` produces `Key-Value Creation.csv`), and the generator fuses only the files written by the current run into `All_telem_results.csv`.
- Categories that still map to Atomic Red Team tests require the Invoke-AtomicRedTeam framework and whatever payloads those tests fetch. On endpoints without internet access those categories fail loudly in the run log instead of silently doing nothing.

## Feature Proofing

As the project expands and evolves, the telemetry generation tool will continue to improve and incorporate new features and capabilities. This ongoing development will ensure that the tool remains relevant and effective in generating and testing telemetry data in line with the Invoke-AtomicRedTeam framework and the project's goals.
